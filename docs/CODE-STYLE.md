# CODE-STYLE — человекочитаемый код

Цель: код, который понимает человек, не писавший его. Проверяется агентом `reviewer` и людьми.

## Язык
- Идентификаторы (классы, функции, переменные) — английские.
- Комментарии, KDoc/TSDoc, сообщения об ошибках и тексты интерфейса — русские.

## Комментарии
1. **Комментарий объясняет «почему», а не «что».**
   Плохо: `// увеличиваем счётчик на 1`.
   Хорошо: `// Лимит глубины защищает от зацикливания, если в данных появится цикл подчинения`.
2. Каждый публичный класс, сервис, репозиторий, контроллер и компонент начинается с краткого комментария: зачем он нужен (1–3 строки).
3. Нетривиальные SQL-запросы (рекурсивные) сопровождаются комментарием: что возвращают и как читаются.
4. Бизнес-правила со ссылкой на `docs/DOMAIN.md`: `// Инвариант 3: у каждого, кроме главы, ровно один линейный руководитель`.
5. Не оставляй закомментированный код и TODO без пояснений.

## Структура и нейминг
- Функция делает одно дело и помещается на экран (ориентир ≤ 30 строк). Длиннее — выдели функции с говорящими именами.
- Имена раскрывают смысл: `findManagementChain`, а не `getData`.
- Никаких «магических» чисел: константы с именем и комментарием (`MAX_TREE_DEPTH = 20`).
- Минимум вложенности: ранний `return`, guard-условия.
- Не изобретай абстракции заранее. Три похожих куска — повод для функции, не для фреймворка.

## Kotlin
- Предпочитай `data class` для DTO, `val` вместо `var`, неизменяемые коллекции.
- Nullable только когда значение реально может отсутствовать (например, `parent` у корня).
- Исключения предметной области (`EmployeeNotFoundException`) — а не `RuntimeException("...")`.
- Форматирование: ktlint (или встроенный форматтер IDE). Статический анализ: detekt — если подключён.

## TypeScript / Angular
- Строгий режим TypeScript включён; `any` запрещён.
- Компоненты маленькие; логика данных — в сервисах и сигналах, а не в шаблонах.
- Шаблон — только отображение; сложные выражения выносим в `computed`.
- Форматирование: Prettier, линтер ESLint (angular-eslint), если подключён.

## SQL
- Ключевые слова в нижнем регистре, один запрос — одна функция репозитория.
- Только параметры (`:name`), никакой конкатенации.

## Пример хорошего комментария
```kotlin
/**
 * Строит дерево подразделений от заданного корня.
 *
 * Рекурсивный запрос ограничен глубиной [MAX_TREE_DEPTH]: если в данных случайно
 * появится цикл, запрос завершится, а не повиснет.
 */
fun findDepartmentTree(rootId: Long, maxDepth: Int): List<DepartmentRow> { ... }
```
